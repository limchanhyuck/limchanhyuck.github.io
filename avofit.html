Avofit · Implementation Details

AI 식단 생성 지연과 쇼핑 API 노이즈를 서버 규칙으로 보정한 다이어트 코치

Avofit은 사용자 TDEE, 목표 칼로리, 선호/알레르기, 월간 예산을 기반으로 30일 식단을 생성하고 장보기 추천까지 연결하는 다이어트 코치 서비스입니다. 핵심은 AI를 붙인 것이 아니라, 식단 생성 지연은 7일 선응답 + 23일 비동기 chunk 처리로, 불안정한 LLM 응답은 재시도 + JSON 정제 + 템플릿 fallback + 칼로리 보정으로 흡수했다는 점입니다.

Overview

내가 맡은 핵심 구현

  • 30일 식단 생성 API와 7일 선응답 + 23일 비동기 chunk 처리 구현
  • LLM 재시도, JSON 정제, 템플릿 fallback, ±10% 칼로리 스케일링 파이프라인 설계
  • 식단 재료를 totalGram·totalCalories·daysCount로 집계해 쇼핑 추천 입력으로 연결
  • 검색어 정규화, 상품 스코어링, AI rerank, budget guard 기반 장보기 추천 구현
  • 체중 기록 UNIQUE + upsert 흐름으로 날짜별 체중 데이터 중복 차단

면접에서 설명할 포인트

  • 전체 생성 대기 예상 60초대를 첫 응답 약 15초 내외로 줄이는 구조를 선택한 이유
  • AI 결과를 그대로 저장하지 않고 서버 도메인 규칙으로 보정한 점
  • 장보기 추천을 단순 검색이 아니라 예산·용량·카테고리 제약 문제로 설계한 점
  • 동일 재료 재조회 시 외부 API 1~2초를 60분 TTL 캐시로 10ms 내외 조회로 줄인 점
30일 월간 식단 생성 범위
60s → 15s 30일 전체 대기 대비 초기 응답 시간 구조상 추정
1~2s → 10ms 동일 재료 상품 조회 캐시 적용 시 추정
±10% 목표 칼로리 범위 이탈 시 grams 재계산
Core Flows

AI 식단 생성 지연을 7일 선응답 구조로 분해

문제 30일 식단을 한 번에 생성하면 사용자가 결과를 보기 전까지 전체 LLM 응답을 기다려야 했습니다.
해결 첫 7일은 동기 생성해 즉시 보여주고, 나머지 23일은 백그라운드에서 chunk 단위로 병렬 생성했습니다.
성과 전체 생성 대기 예상 60초대를 초기 응답 약 15초 내외로 줄이는 구조를 만들었습니다.

AI 결과를 서버 규칙으로 보정해 식단 품질 유지

문제 AI 응답이 실패하거나 목표 칼로리에서 벗어나면 하루 식단 총량과 추천 품질이 흔들릴 수 있었습니다.
해결 AI 실패 시 템플릿으로 fallback하고, 목표 범위를 벗어난 식단은 grams를 재계산해 영양값을 다시 산출했습니다.
성과 생성 결과가 목표 칼로리의 ±10%를 벗어나면 자동 보정되도록 서버 규칙을 고정했습니다.

식단 재료를 장보기 추천 입력으로 집계

문제 30일 식단 데이터가 날짜·끼니·재료 단위로 흩어져 있어 쇼핑 추천에 필요한 총량을 바로 쓰기 어려웠습니다.
해결 DB에서 재료명 기준으로 총 gram, 총 calories, 등장 일수를 집계하고 그 결과를 상품 추천과 예산 guard에 연결했습니다.
성과 동일 재료 상품 재조회는 60분 TTL 캐시로 외부 API 1~2초 호출을 10ms 내외 메모리 조회로 줄일 수 있게 했습니다.
코드 스니펫 
SELECT mi.food_name AS ingredientName,
       SUM(mi.grams) AS totalGram,
       COUNT(DISTINCT mi.meal_plan_day_id) AS daysCount
FROM meal_items mi
WHERE mi.meal_plan_day_id IN (
    SELECT id FROM meal_plan_days WHERE meal_plan_id = #{planId}
)
GROUP BY mi.food_name

체중 기록 중복을 DB 제약과 upsert로 차단

문제 같은 날짜의 체중 기록이 중복되면 체중 추이, BMI 계산, 아바타 상태가 서로 다른 기준으로 흔들릴 수 있었습니다.
해결 user_id + record_date UNIQUE 제약을 두고 같은 날짜 기록은 insert 대신 update하도록 처리했습니다.
성과 날짜별 체중 데이터를 1건으로 고정해 대시보드의 체중 변화, BMI, 5단계 아바타 상태 계산 기준을 일관되게 유지했습니다.
