Duckchi Pay Service · Implementation Details

정산 생애주기를 끝까지 책임지는 Pay Backend 설계

Duckchi는 모임 정산을 빠르게 끝내고, 정산 이후에도 소비 데이터를 남겨 분석까지 연결하는 더치페이 서비스입니다. Pay Service에서 모임·정산 백엔드를 담당하며, 정산 요청 생성부터 송금 처리, 권한 검증, 금융 예외 대응까지 정산의 전체 생애주기를 설계·구현했습니다.

Overview

내 역할

  • Pay Service에서 정산 요청 생성, 다건 송금, 수동 완료, 정산 상세/대기 조회 API를 설계·구현
  • 권한 검증, 멤버십 검증, 정산 상태 전이, 외부 금융 API 오류 매핑까지 정산 도메인 규칙 정리
  • 자동이체 동의 확인과 fail-safe 분기까지 프론트 흐름과 백엔드 에러 계약을 함께 설계
  • 구현 계획서 27건, 개발일지 29건, 트러블슈팅 15건 등 총 71건 문서화

핵심 성과

  • 모임/정산 핵심 API 13개를 설계·구현하며 정산 요청부터 송금 완료까지 핵심 흐름을 구축했습니다.
  • 중복 정산 요청 차단, 건별 독립 트랜잭션, 멱등키 적용으로 정산 무결성과 재시도 안정성을 확보했습니다.
  • Partial Success, 외부 금융 오류 복원, fail-safe 분기로 운영 복구성과 사용자 안전성을 함께 높였습니다.
Architecture

서비스 아키텍처

Gateway, Core, Payment, Insight 서버를 분리하고, 결제 요청은 동기 흐름으로, 분석·알림은 Redis/Kafka 기반 비동기 흐름으로 분리했습니다. 운영 관점에서는 Jenkins 기반 배포, Nginx 리버스 프록시, RDS 분리, 외부 금융/푸시/OCR 연동까지 고려한 구조입니다.

실시간 랭킹 반영은 revision 원자 증가 + event cache + SSE ranking.updated push 구조를 사용해 폴링 없이 순서를 보장하면서 즉시 갱신되도록 구성했습니다.

다건 송금의 Partial Success 설계

SettlementServiceImpl.java · line 131
문제

배치 송금에서 한 건 실패가 전체 실패로 이어지면 사용자와 운영자 모두 복구 비용이 커졌습니다.

해결

실패 ID를 수집하고, 잔액 부족은 우선 에러로 분리해 성공 건은 유지하도록 설계했습니다.

성과

성공 건은 그대로 확정하고 실패 건만 재처리할 수 있어 운영 복구 속도가 빨라졌습니다.

List<Long> failedSettlementIds = new ArrayList<>();
boolean hasInsufficientBalanceFailure = false;

for (Long settlementId : sortedSettlementIds) {
    try {
        settlementTransferExecutor.transferOne(currentUserId, settlementId);
    } catch (CustomException ex) {
        failedSettlementIds.add(settlementId);
        if (ErrorCode.SETTLEMENT_INSUFFICIENT_BALANCE.equals(ex.getErrorCode())) {
            hasInsufficientBalanceFailure = true;
        }
    }
}

if (!failedSettlementIds.isEmpty()) {
    if (hasInsufficientBalanceFailure) {
        throw new CustomException(ErrorCode.SETTLEMENT_INSUFFICIENT_BALANCE, failedSettlementIds);
    }
    throw new CustomException(ErrorCode.SETTLEMENT_TRANSFER_PARTIAL, failedSettlementIds);
}

@Transactional(propagation = Propagation.REQUIRES_NEW)
public void transferOne(Long currentUserId, Long settlementId) {
    String financeRequestUniqueNo =
        settlementTransferIdempotencyService.ensureFinanceRequestUniqueNo(settlementId);

    Settlement settlement = settlementRepository.findByIdForUpdate(settlementId)
        .orElseThrow(() => new CustomException(ErrorCode.SETTLEMENT_NOT_FOUND));

    validatePayerAuthorization(currentUserId, settlement);
    validatePendingStatus(settlement);
}

외부 금융 오류를 도메인 에러로 정교하게 복원

성과

try {
    TransferResponse response = financeClient.transfer(transferRequest);
    validateFinanceResponse(response);
    return response;
} catch (Exception ex) {
    if (hasInsufficientBalanceSignal(ex)) {
        throw new CustomException(ErrorCode.SETTLEMENT_INSUFFICIENT_BALANCE);
    }
    throw new CustomException(ErrorCode.FINANCE_API_ERROR);
}

private void validateFinanceResponse(TransferResponse response) {
    if (response == null || response.header() == null) {
        throw new CustomException(ErrorCode.FINANCE_API_ERROR);
    }
    if (FINANCE_INSUFFICIENT_BALANCE_CODE.equals(response.header().getResponseCode())) {
        throw new CustomException(ErrorCode.SETTLEMENT_INSUFFICIENT_BALANCE);
    }
}
